## Архитектурный паттерн

```
Domain (apps) → Repository → Service → API → Tasks
```

### Уровни абстракции:

1. **Domain (apps/)** - Слой доменных моделей
2. **Repository** - Слой доступа к данным
3. **Service** - Бизнес-логика
4. **API** - REST API слой
5. **Tasks** - Асинхронные задачи (Celery)

## Следующие шаги

1. Установить зависимости: `pip install django-environ`
2. Создать резервную копию БД
3. Выполнить миграции: `./manage.py makemigrations && ./manage.py migrate`
4. Запустить тесты: `pytest backend/tests/`
5. Обновить CI/CD pipeline

## Примечания

- Устаревшие файлы (models.py, serializers.py, views.py) можно удалить после проверки
- Для production установить `DEBUG = False` в `settings/prod.py`
- Настроить правильные `DJANGO_SECRET_KEY` и `DJANGO_ALLOWED_HOSTS`
